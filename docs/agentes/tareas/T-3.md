# T-3 — Effort, vista por modelo, filtro de proyecto y `--por` en la terminal

**Contexto:** pedido del equipo: el consumo tiene que verse por modelo y por effort, por proyecto, y poder elegir
desde la terminal qué ver.
**Archivos permitidos:** `fuentes/*.js`, `lib/agregar.js`, `lib/formato.js`, `bin/telemetria.js`, `test/fuentes.test.js`,
`test/agregar.test.js`, `test/cli.test.js`, `README.md`, `docs/agentes/reportes/T-3.md` (nada fuera de aquí; `lib/html.js`
es de otra tarea en paralelo)
**Depende de:** `docs/datos.md` (contrato actualizado: `effort`, `filtro`, `modelos`, `proyectos[].modelos`; no cambiarlo)
**Agente / modelo:** codex
**Modo:** escritura

## Objetivo

1. Cada registro trae `effort` (o null).
2. El agregado trae `filtro`, `modelos` (por modelo sumando herramientas, con sus efforts) y `proyectos[].modelos`.
3. La terminal muestra primero **por modelo** y **por modelo + effort**, y se puede elegir qué sección ver y filtrar por
   proyecto.

## Contrato (no cambiarlo)

### Dónde está el effort (verificado en una PC real)

| Fuente | Campo |
|---|---|
| Claude Code | en cada línea `assistant`: `perTurnEffort` (si no, `effort`), p. ej. `"xhigh"`, `"medium"` |
| Codex | `turn_context.payload.effort` (p. ej. `"high"`); vale para los token_count siguientes, igual que `model` |
| Antigravity | no hay campo: si el modelo termina en `-minimal`, `-low`, `-medium`, `-high` o `-xhigh` (p. ej. `gemini-3.8-flash-medium`), ese sufijo es el effort; el nombre del modelo queda completo |
| OpenCode | `data.variant` si existe (hoy no viene); si no, null |
| Gemini CLI, orquestadores | null |

### Agregado (`lib/agregar.js`)

Exactamente como `docs/datos.md`. `agregar` recibe además `filtro` (`{ proyecto }` o null) y lo devuelve tal cual.
`modelos[].herramientas`: nombres únicos ordenados. `modelos[].efforts` y `proyectos[].modelos` por entrada descendente.

### Terminal (`bin/telemetria.js`)

`telemetria [días|todo] [--por <vista>] [--proyecto <texto>]` y lo mismo para `json` y `html`.

- `--proyecto <texto>`: deja solo los registros cuyo proyecto contiene el texto (sin distinguir mayúsculas) **antes**
  de agregar; el encabezado dice `· proyecto: <texto>` y el agregado trae `filtro`.
- `--por <vista>` muestra solo esa sección (sin `--por`, todas, en este orden):
  1. `modelo`: `Modelo | Herramientas | Sesiones | Llamadas | Entrada | Caché | Salida | Razon. | Costo US$`;
  2. `effort`: `Modelo | Effort | Llamadas | Entrada | Caché | Salida | Razon. | Costo US$` (effort null → `—`);
  3. `herramienta`: la tabla actual por herramienta (y la de herramienta + modelo debajo);
  4. `dia`: la tabla actual por día;
  5. `proyecto`: proyecto con sus modelos debajo, sangrados: `Proyecto / Modelo | Effort | Llamadas | Entrada | Salida`
     (los 10 primeros proyectos, hasta 5 modelos cada uno);
  6. límites y avisos siempre al final.
  Vista desconocida → mensaje con las vistas válidas y código 2.
- `--ayuda` explica las vistas y el filtro.
- `README.md`: actualiza la tabla de comandos y "En la terminal sale" con `--por`, `--proyecto` y las secciones nuevas;
  agrega en "Cómo leer los números" qué es effort y de dónde sale en cada herramienta (tabla de arriba, corta). Agrega
  una pregunta frecuente: **¿El reporte consume tokens? No:** `telemetria` es un programa local que solo lee
  archivos; ni la terminal ni el HTML usan IA. Solo gastarías tokens si le pides a una IA que lo corra y lea la salida.
